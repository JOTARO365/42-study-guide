### A8. ตัวอย่าง minitalk ประกอบ byte ผิดตัว (`data.js:1631-1644`)

บล็อกอยู่ใต้หัวข้อที่กำลังอธิบาย `'A'` (0100 0001) แต่ลำดับ signal ในตัวอย่าง (USR2 นำ) ประกอบออกมาได้ `1000 0001` = **129 (0x81)** ไม่ใช่ 'A'. ขัดกับตัวอย่างเดียวกันที่ `:1544-1550` ซึ่งถูกต้อง

### A9. minitalk — note เรื่อง UTF-8 ขัดกับเนื้อหาตัวเอง (`data.js:1727`)

note บอกว่า "ถ้า server ใช้ `ft_printf("%c", c)` ทีละ byte จะไม่เห็นภาษาไทย/emoji" — แต่ `:1719` และทริค 6 (`:1934`) บอกตรงข้ามว่าใช้ได้เพราะ terminal ประกอบเอง. ของถูกคือ **ใช้ได้** (`%c` เขียนผ่าน `write` ทีละ byte, terminal บัฟเฟอร์แล้วประกอบเอง) → note นี้ผิด ควรลบ

### A10. fract-ol — โค้ด palette คอมไพล์ไม่ผ่าน (`data.js:1483-1486`)

```c
r = 9.0  * (1-t) * t*t*t * 255;   // r เป็น double
return ((r << 16) | (g << 8) | b); // << บน double = compile error
```

### A11. philosophers — "torn read" เกินจริง (`data.js:2512-2519`)

อธิบายว่า `long last_meal` 64-bit ถูกเขียนเป็น 2 ครึ่ง แล้ว monitor อ่านได้ค่าผสม 4096. บน x86-64 (เครื่อง 42) การอ่าน/เขียน 64-bit ที่ align แล้วเป็น atomic — เคสนี้ไม่เกิดจริง. เหตุผลที่ต้องล็อกจริง ๆ คือ compiler reordering/caching + เป็น UB ตามมาตรฐาน ซึ่งยังทำให้ข้อสรุป (ต้องล็อก) ถูก แต่ "หลักฐาน" ที่ยกมาไม่จริง

### A12. AI — ตัวเลข token ภาษาไทยขัดกันเอง (`data.ai.js:153` vs `:169`)

`:153` บอก "สวัสดี = 3 tokens"; `:169` บอก "ก = 3 tokens (byte fallback)". ถ้า 'ก' ตัวเดียว = 3 tokens แล้ว "สวัสดี" (6 ตัว) ต้องมากกว่า 3 มาก. อีกจุด `:155` บอก "ไทยแพงกว่า 2-3 เท่า" แต่ตัวอย่าง `:162` คำนวณได้ 1.75 เท่า

### A13. HNSW — ตัวเลข speedup ขัดกันเอง (`data.ai.js:902-904` vs `:948`)

### A14. AI cost — Scenario 2 คำนวณผิดหน่วย (`data.ai.js:2206-2224`)

```
เขียนไว้: ง่าย (70%): 700 × ($0.25+$1.25)/M = $0.00105
```
`700` คือ *จำนวน request* แต่ถูกเอาไปคูณกับราคา *ต่อ token* → ผลลัพธ์ $2.30/วัน ผิด. คำนวณถูกด้วยสมมติฐานเดิม (3000 in / 500 out) ได้ประมาณ **$5.9/วัน**

และบรรทัดสรุป `:2224` บอก "Model routing + caching = ประหยัดสูงสุด" ทั้งที่ตารางแสดง Scenario 2 (routing อย่างเดียว) ถูกกว่า Scenario 3 (caching อย่างเดียว) — ไม่มี scenario ที่รวมทั้งสองอย่างให้ดู ข้อสรุปจึงไม่ตามมาจากตาราง

## B. ขัดกับ norm ที่เว็บนี้สอนเอง

`CLAUDE.md` และหน้า cub3d/miniRT ย้ำว่า norm **ห้าม ternary `?:` และห้าม `for`** — แต่โค้ดตัวอย่างในหน้าอื่นใช้เอง:

| ที่ | ของที่ผิด |
|---|---|
| `data.js:823` (pipex) | `return (access(cmd, X_OK) == 0 ? ft_strdup(cmd) : NULL);` |
| `data.js:2061-2062` (fdf) | `sx = (x0<x1) ? +1 : -1;` |
| `data.js:2268` (fdf) | `t = (steps != 0) ? i/steps : 0;` |
| `data.js:4039-4040` (miniRT) | `for (y = 0; ...)` / `for (x = 0; ...)` |

ขณะที่ `data.js:4239` (cub3d) เขียนชัดว่า "boolean arithmetic, เลี่ยง `?:` ตาม norm" → ผู้เรียนจะสับสนว่าตกลงใช้ได้หรือไม่ได้ **ควรทำให้เหมือนกันทุกหน้า**

หมายเหตุ: หน้า exam_rank02 บอกถูกแล้วว่าสอบไม่ตรวจ norm — ตรงนั้นไม่ต้องแก้

### C2. ข้อความที่อ่านไม่รู้เรื่อง

`data.js:4497` (ตารางบั๊กยอดฮิต cub3D) ช่อง "อาการ" เขียนว่า **"norm 0 OK ทั้งที่โค้ดดี"** — อ่านแล้วแปลว่า "norm ผ่านทั้งที่โค้ดดี" ซึ่งไม่ใช่อาการของบั๊ก. ที่ตั้งใจคือ "**norm ไม่ผ่านทั้งที่โค้ดดูถูกต้อง**"

### C3. ฟิลด์ผิดสคีมา (ไม่พังแต่รก)

`{ note: "...", lang: "txt" }` — block ชนิด `note` ไม่มีฟิลด์ `lang` ที่ `data.js:197, 245, 281, 1686, 1727`

### C4. typo เล็ก

- `data.js:197` เว้นวรรคนำหน้า: `" normalization เป็น O(n²)"`
- `data.js:291` "MATOID theory" → **matroid**
- `data.ai.js:107` `_softmax(logits, ...)` — ขีดล่างนำหน้าเกินมา

### C5. สำนวนที่ควรปรับ (ตามเกณฑ์ stop-slop)

1. **เน้นมากเกินจนไม่เหลือน้ำหนัก** — `**ตัวหนา**` ถี่มากในหลายย่อหน้า เมื่อทุกอย่างสำคัญเท่ากันก็เท่ากับไม่มีอะไรสำคัญ เสนอ: ย่อหน้าหนึ่งเน้นไม่เกิน 1–2 จุด
2. **วลีซ้ำข้ามหน้า** — "ไม่ได้สุ่มมา" (push_swap `:248`, fract-ol `:1291`), "ภาพในหัว:" ขึ้นต้นเจาะลึกเกือบทุกอันในครึ่งหลังของไฟล์ ทำให้อ่านรวดเดียวรู้สึกเป็นสูตรสำเร็จ เสนอ: สลับวิธีเปิดบ้าง
3. **คำแรงเกินบริบท** — `data.js:264, 269` "← ห้ามหวัง" ในตารางเทียบ algorithm อ่านเหมือนดุคนอ่าน เสนอ: "เกินเกณฑ์หลายเท่า"
4. **สัญลักษณ์ตกแต่ง** — `★` (`:159, :653, :1346, :3465`) และ `🔒` (`:656`) แทรกในบล็อกโค้ด ไม่เพิ่มความหมาย
5. **em dash หนามาก** — stop-slop แนะให้เลี่ยง; ในภาษาไทยยังพอรับได้ แต่บางย่อหน้ามี 3–4 ตัว ควรแตกเป็นประโยคแทน

## D. เนื้อหาที่ขาด (ไม่ผิด แต่หน้าที่สอนเรื่องนั้นควรมี)

หน้า `ai_llm` สอน prompt caching ลึกถึงขั้นคำนวณ break-even แต่ไม่มี 3 เรื่องที่ทำให้ caching ใช้จริงแล้วไม่ติด:

1. **TTL 1 ชั่วโมง** — `cache_control: {type:"ephemeral", ttl:"1h"}` ราคา write เป็น **2×** (ไม่ใช่ 1.25×) → break-even ขยับเป็น ~3 รอบ
2. **prefix ขั้นต่ำที่แคชได้** — 512 token (Opus 5) / 1024 (Sonnet 5, Opus 4.8) / 4096 (Opus 4.6, Haiku 4.5). สั้นกว่านี้ **แคชเงียบ ๆ ไม่ทำงาน ไม่มี error** — เป็นกับดักอันดับ 1 ของเรื่องนี้
3. **วิธีตรวจว่า cache ติดจริง** — `usage.cache_read_input_tokens` ถ้าเป็น 0 ตลอดแปลว่ามีตัวทำลาย cache (timestamp/UUID ใน system prompt) และมี **เพดาน 4 breakpoint** ต่อ request

เพิ่มเติม: ลิงก์ `docs.anthropic.com/...` ทุกจุด (`data.ai.js:203, 205, 618-630, 2291-2296, 2637`) ตอนนี้ redirect ไป `platform.claude.com` — ยังเข้าได้แต่ควรอัปเดต

## E. ฉบับภาษาอังกฤษ (`data.en.js`)

**คุณภาพภาษา: ดี** — เป็นอังกฤษที่เขียนใหม่ ไม่ใช่แปลตรง อ่านลื่น น้ำเสียงตรงกับ TH ไม่ต้องแก้เชิงสำนวน

**แต่:** EN สะท้อน TH แบบ 1:1 รวมถึง**ข้อผิดพลาดทุกข้อในหมวด A** — model ID ตายแล้ว, ราคาผิด, `budget_tokens`, ตัวเลขขัดกันเองของ push_swap, เกณฑ์คะแนน ทุกอย่างซ้ำอยู่ใน `data.en.js` ที่บรรทัด 3772–5854

→ **ทุกการแก้ในหมวด A ต้องแก้ 2 ที่เสมอ** ควรทำเป็นคู่ในคอมมิตเดียว

จุดที่ EN ต่างจาก TH: `data.en.js:11` มีย่อหน้าเปิดที่ TH ไม่มี (ไม่ใช่ปัญหา แต่ทำให้เนื้อหาสองภาษาไม่ตรงกันเป๊ะ)
